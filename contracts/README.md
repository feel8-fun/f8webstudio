# Portable publication contracts

P0 contracts belong to `f8studio_core.publication` and do not import the server,
Cloud, installed catalogs or runtime. `publication.gen.json` is generated by
`scripts/web_studio/generate_contracts.py`; consumers validate against this
artifact instead of maintaining their own models.

- `f8publication/1` contains a typed graph/component, immutable manifest and SHA-256.
- `f8publication-manifest/1` records format/version, explicit license, source and
  extension ownership of every service/operator definition (including hosts).
- `f8component/1` uses graph definition refs and stable port IDs. An operator's
  `serviceId` names an included service or an explicit `hostBindings` entry.
  Hosts carry a service definition ref, never local host configuration.
  Endpoints identify retained ports whose external connection was cut. They do
  not generate runtime connections, input nodes or mandatory parameters.
- Dependency compatible versions are explicit accepted versions; empty means any
  version. This format does not interpret SemVer ranges. Protocol and capability
  requirements are independent. Resolution never installs or executes code.
  `diagnose_dependencies` returns codes and actionable missing items. Embedded
  definitions remain usable for preview without installed implementations.

## Version and migration policy

The capabilities response exposes accepted formats and hash profiles. Current
readers accept graph 4 and previous graph 3, SDK specs 2 and previous specs 1,
and local documents 3 and previous documents 2. Portable component 1 is the first
portable version. `decode_component` explicitly converts local component 1/2
through validated authoring models; it never relabels the old payload.
Legacy graph definition hashes are verified before migration. Decoding a
publication verifies its original hash before migration/preview. New publication
writes use graph 4 or portable component 1. Definition defaults/examples are
preserved; instance values are projected through persistence/publication policy.

Unknown publication fields and unsupported versions fail with explicit errors.
New semantics require a content/manifest version; an API release does not itself
change content versions. Committed fixtures are the compatibility baseline and
must not be regenerated to hide a regression. Cloud session 1 is not accepted:
its separate conversion/reporting tool belongs to P4. Resources and component
parameters are not supported in these contracts.

## Hash profile `f8publication-hash/1`

Hash the typed, default-expanded `{hashProfile, manifest, content}` projection.
Exclude graph metadata (local project/graph IDs); editing revisions, timestamps,
local IDs and live state are absent from portable content. Preserve graph node
and port IDs, display names, all definitions, layout, and ordered `nodeOrder`.
Sort declared sets: connections by edge ID, layout by node ID, host bindings by
binding ID, endpoints by endpoint ID, dependencies by extension ID, dependency
string lists by Unicode scalar order, and operator requirements by class pair.
All other arrays, including schema examples and user values, retain their order.

The hash preimage is UTF-8 compact JSON of `[profile, taggedTree]`. Tree tags are
`null`, `boolean`, `number`, `string`, `array`, `object`; values follow each tag.
Objects contain sorted `[key, taggedValue]` pairs (Unicode scalar order).
Numbers use their IEEE-754 binary64 big-endian 16-character lowercase hex token;
normalize negative zero to positive zero. Integers must be within the JavaScript
safe integer range. Nonfinite numbers and unpaired Unicode surrogates fail.
This avoids Python/JavaScript decimal-printing differences without changing the
JSON wire representation or colliding with user-provided objects/arrays.

Python and Web tests consume the same `fixtures/hash-v1.json` vectors and actual
`graph-v1.json`/`component-v1.json` publications. The Web hash helper receives
validated, default-expanded output contracts; raw incoming JSON first requires
schema validation and default expansion. Content hash is independent of runtime
semantic hash and never acts as publisher authentication or an installation lock.
Cloud publication deduplication, concurrency and durable idempotency belong to P2.
